# HotelManager Web

Адаптивный учебный сайт гостиницы на HTML, CSS и JavaScript с сервером Node.js и общей SQLite-базой. На телефоне и компьютере используется один адрес: данные гостей, бронирований, оплат и уведомлений хранятся на сервере.

## Сайт на GitHub Pages

Исходники: https://github.com/Ilatrion/-

После успешной публикации GitHub Pages: https://ilatrion.github.io/-/

Интерфейс действительно размещается на GitHub Pages. HTTP API и общая база работают на Sites: https://hotelmanager-web-school-20261117.elegantgear3.chatgpt.site. Это не перенаправление и не iframe. Обе версии используют одну базу; существующие аккаунты и PIN сохраняются.

Workflow `.github/workflows/pages.yml` проверяет код и публикует интерфейс при изменении main. Если GitHub сообщает, что Pages не включён, откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**, затем запустите **Actions → Deploy HotelManager to GitHub Pages → Run workflow**. Установленный Git или Node.js для посетителей не требуется.

Для локальной сборки интерфейса: `node scripts/build-pages.mjs`. Папка `pages/` содержит только публичные HTML/CSS/JS и фото, без базы и секретов. Конфигурация API — `pages/config.js`. Разрешённый Origin сервера — строго `https://ilatrion.github.io`.

На GitHub Pages используется отдельная серверная сессия с токеном в sessionStorage текущей вкладки; cookie другого сайта не требуются. На самом Sites и локальном Node-сервере остаётся HttpOnly-cookie. Завершайте сеанс кнопкой «Выйти» на общем компьютере. Секрет сессии не хранится в репозитории или URL.

## Быстрый запуск на Windows

1. Установите **Node.js 24 LTS** с https://nodejs.org/ (версия 22.13+ также подходит).
2. Скачайте проект кнопкой **Code → Download ZIP**, распакуйте архив. Откройте терминал в папке, где лежит `server.mjs`.
3. При первом запуске задайте пароль новой базы (см. раздел «Учётные записи»), затем выполните:

```powershell
node server.mjs
```

4. Откройте **http://localhost:3000**. Терминал оставьте открытым. Остановка — Ctrl+C. Можно использовать `start-windows.cmd`.

Устанавливать npm-пакеты не требуется. Двойной щелчок по index.html сервер не запускает.

## Открыть с телефона или другого компьютера

На компьютере-сервере в PowerShell:

```powershell
$env:HOST="0.0.0.0"
node server.mjs
```

Командой `ipconfig` найдите IPv4 компьютера в вашей Wi-Fi/локальной сети, например `192.168.1.10`. На телефоне в той же сети откройте **http://192.168.1.10:3000**. При запросе Windows разрешите доступ Node.js в частной сети. Все пользователи должны открывать адрес одного сервера. `localhost` на телефоне означает сам телефон.

Linux/macOS:

```bash
HOST=0.0.0.0 PORT=3000 node server.mjs
```

Для доступа через интернет нужен работающий Node.js-хостинг с постоянным диском и HTTPS или поддерживаемый Worker с D1. **GitHub хранит исходники; GitHub Pages не запускает этот сервер и общую базу.** Не выкладывайте файл базы в репозиторий.

## Учётные записи

На опубликованном сайте используйте ранее выданные вам учётные данные. Гость также может зарегистрировать личный аккаунт. Пароли действующих аккаунтов не включаются в публичные исходники.

Для **новой локальной базы** перед первым запуском задайте свой пароль администратора длиной от 12 символов. В PowerShell:

```powershell
$env:HOTEL_ADMIN_PASSWORD="ЗАМЕНИТЕ_СВОИМ_НОВЫМ_ПАРОЛЕМ"
node server.mjs
```

Вход — логин `admin` и заданный вами пароль. Это значение нужно ввести на своём компьютере; в GitHub его не отправляйте. Для Linux используйте `HOTEL_ADMIN_PASSWORD='ваш-личный-пароль' node server.mjs`. Дополнительные начальные пароли при необходимости задаются переменными HOTEL_GUARD_PASSWORD, HOTEL_GUEST_PASSWORD, HOTEL_GUEST2_PASSWORD; без них начальные учётные записи получают случайные пароли. Для гостевого доступа удобнее регистрация.

Существующая база и её пароли при обновлении приложения не меняются. При первом входе придумайте PIN из 4–6 цифр и сохраните одноразовый код восстановления. После четырёх ошибок вход блокируется на пять минут. Камера предлагается персоналу по нажатию при первом входе. Руководства доступны в разделе помощи.

## Что реализовано

- Адаптивный интерфейс телефона и компьютера, светлая и тёмная темы, кнопка «Домой» во всех внутренних разделах.
- 20 номеров: Стандарт, Комфорт, Люкс; все доступны для 1–3 гостей с учётом дат, занятости и подготовки номера.
- Автозаполнение контактов и параметров поездки, серверный расчёт ночей и стоимости. После бронирования открывается карточка проживания.
- Бронирование, изменение, отмена, заселение, переселение, выезд, уборка и ремонт; проверка пересечений дат.
- Услуги, счета, учёт оплат и возвратов. Учебная платёжная форма СБП/QR с настоящим QR-кодом, выбором успешного/ошибочного результата и защитой от повторного проведения. **Деньги не переводятся; банковские реквизиты не запрашиваются.**
- Серверное разграничение прав; гость не может прочитать чужую бронь или вызвать административную команду через API.
- Уведомления администратора о действиях гостей, журнал событий, фильтры, отчёты CSV/печать, экспорт данных JSON без секретов входа.
- Учебные модули 6–16: задачи, заметки, импорт/экспорт, QR-проверка демонстрационного пропуска, синхронизация, безопасность. Это веб-адаптация функций; Android API заменены браузерными возможностями.
- Обновление данных между устройствами каждые 15 секунд. Несохранённые формы не заменяются автоматическим обновлением.

## Где база и как сохранить работу

При первом запуске создаётся **data/hotel.sqlite**. При перезапуске данные сохраняются. Для полной резервной копии остановите сервер и скопируйте всю папку `data`. Переносите её вместе с проектом на другой сервер. Для выгрузки деловых данных используйте экспорт администратора. Он не содержит пароли, PIN, коды восстановления и cookie сессий; обратный импорт полной базы через интерфейс не предусмотрен.

HTTPS необходим для камеры при доступе с телефона по сети. На `localhost` камера обычно работает и без HTTPS; при отказе, отсутствии камеры или BarcodeDetector предусмотрен ручной ввод учебного кода `HOTEL:guest`. Код — демонстрационная проверка, он не подтверждает личность.

## Проверки и структура

```bash
npm test
node tests/hotel.test.mjs
npm run build
```

28 отдельных проверок прав, конфликтов бронирования, расчёта стоимости, платежей, PIN и двух клиентов одной базы. `public/` — интерфейс; `src/engine.mjs` — правила; `src/service.mjs` — HTTP API; `server.mjs` — локальный сервер; `drizzle/` — схема; `tests/` — проверки. `npm run build` создаёт Worker для Sites; для обычного запуска сборка не нужна.

Браузерная проверка и скриншоты в среде сборки недоступны. Выполнены проверки JavaScript, серверные тесты и проверка собранного Worker; окончательный внешний вид следует проверить в вашем браузере.
